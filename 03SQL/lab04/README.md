# Семинар 4 — Теоретико-множественные операторы в PostgreSQL

Разбираем задания по одному. Перед каждым заданием студент пробует написать
идею и запрос; после совместного разбора проверенный запрос добавляется в
[`solution.pqsql`](solution.pqsql).

## Учебная база

PostgreSQL 16 запущен через Colima в контейнере `bivt-lab04-postgres`.
Соединение доступно только с этого компьютера.

| Параметр | Значение |
| --- | --- |
| Сервер | `127.0.0.1` |
| Порт | `5432` |
| База данных | `adventureworks_lt` |
| Пользователь | `lab` |
| Пароль | `lab` |

Открыть интерактивный `psql` можно командой:

```bash
docker exec -it bivt-lab04-postgres psql -U lab -d adventureworks_lt
```

Структура таблиц загружена из [`schema.sql`](schema.sql). Официальный скрипт
данных из задания не приложен, поэтому [`seed.sql`](seed.sql) содержит небольшой
самостоятельно подготовленный набор для практики. Этот набор уже загружен в
учебную базу. Это не оригинальные данные AdventureWorksLT. Он включает клиентов
с обоими типами адреса и только с одним, пересекающиеся и отдельные города, а
также товары для всех ценовых условий.

Чтобы пересоздать схемы и загрузить набор заново из корня репозитория, выполните:

```bash
docker exec -i bivt-lab04-postgres psql -v ON_ERROR_STOP=1 -U lab -d adventureworks_lt < 03SQL/lab04/schema.sql
docker exec -i bivt-lab04-postgres psql -v ON_ERROR_STOP=1 -U lab -d adventureworks_lt < 03SQL/lab04/seed.sql
```

## Задача 1. Адреса клиентов

### 1.1. Платёжные адреса

Для клиентов с типом адреса `Main Office` получить название компании
(`companyname`), первую строку адреса (`addressline1`), город (`city`) и
вычисляемый столбец `addresstype` со значением `Billing`.

### 1.2. Адреса доставки

Для клиентов с типом адреса `Shipping` получить те же сведения и вычисляемый
столбец `addresstype` со значением `Shipping`.

### 1.3. Общий список адресов

Объединить результаты пунктов 1.1 и 1.2, отсортировать по названию компании и
типу адреса и вернуть первые 10 строк.

**Тема:** `UNION`, сортировка и ограничение общего результата.

## Задача 2. Фильтрация адресов клиентов

### 2.1. Только главный офис

Вернуть названия компаний с адресом `Main Office`, у которых нет адреса
`Shipping`.

### 2.2. Оба типа адреса

Вернуть названия компаний, у которых есть и адрес `Main Office`, и адрес
`Shipping`.

**Тема:** `EXCEPT` и `INTERSECT`.

## Задача 3. Города сотрудников и клиентов

### 3.1. Все города без дубликатов

Вернуть пары `city`, `countryregion` из городов сотрудников и адресов клиентов;
повторяющиеся пары должны появиться один раз.

### 3.2. Города только сотрудников

Вернуть пары города и страны/региона, где работают сотрудники, но нет адресов
клиентов.

### 3.3. Общие города

Вернуть пары города и страны/региона, присутствующие у сотрудников и клиентов.

**Тема:** `UNION`, `EXCEPT`, `INTERSECT` для нескольких столбцов.

## Задача 4. Работа с каталогом товаров

### 4.1. Товары дороже 50 или без указанного цвета

Вернуть названия товаров с `listprice > 50` вместе с названиями товаров, у
которых `color` не задан; повторов быть не должно. Заголовок этого пункта в PDF
говорит о товарах со скидкой, хотя условие использует цену `listprice > 50`.

### 4.2. Цвета дорогих товаров и Components

Вернуть цвета товаров с `listprice > 1000`, которые также встречаются у товаров
категории `Components`.

**Тема:** объединение и пересечение результатов с товарным каталогом.

## Задача 5. UNION ALL и агрегация

### 5.1. Сводный список категорий и моделей

Объединить через `UNION ALL` названия из `production.productcategory` и
`production.productmodel`, вернув столбцы источника (`категории` или `модели`)
и названия.

### 5.2. Недорогие товары без цвета

Вернуть названия товаров дешевле 100, отсутствующие среди товаров с указанным
цветом.

**Тема:** сохранение строк через `UNION ALL` и разность наборов.

## Порядок работы

Для каждого подпункта сначала пришлите свою идею или SQL. Мы разберём столбцы,
фильтры и операцию над множествами, затем проверим запрос на учебных данных и
только после этого запишем итоговый вариант в `solution.pqsql`.
