# PostgreSQL для публичной демонстрации

Это альтернативная реляционная реализация API. Основная версия курсовой и
пример SQL Graph находятся в T-SQL-файлах [`../`](../). PostgreSQL не выдаётся
за реализацию SQL Graph: подписки здесь представлены обычной таблицей связей.

Нужен PostgreSQL 16+; хеши вычисляет встроенная функция `sha256`. Расширений,
моделей, OCR, очереди индексации и RAG нет. Документы доступны сразу после
загрузки; PDF/DOCX хранятся в `social.documentversion.filebytes`, текстовые
документы в `plaintext`. История версий остаётся в базе.

## Установка

Используйте **новую отдельную пустую базу**. Скрипты не являются миграцией
существующей RAG-базы. Если найдены старые схемы `knowledge` или `assistant`,
установка останавливается до изменений. Не удаляйте прежнюю базу: сначала
сделайте резервную копию, затем согласуйте отдельный перенос пользователей,
сообществ, материалов, версий документов и связей. Файлы из прежней
`knowledge.documentversion` нельзя удалять вместе с индексом.

Порядок:

1. `00-schema.sql`: учётные записи, профили, внешние идентификаторы Firebase,
   сообщества, материалы, подписки, членство, авторство, размещение, комментарии,
   реакции, версии постов/комментариев/документов и аудит (16 обычных таблиц).
2. `01-access.sql`: проверка доступа к сообществам и материалам.
3. `03-social-write.sql`: транзакционные операции соцсети и загрузка документов.
4. `04-social-read.sql`: чтение с проверкой текущего доступа.
5. `06-recommendations.sql`: прямая SQL-лента, без сохранённых рекомендаций.
6. `07-security.sql`: ограниченная роль API и разрешения на функции.

Пропуски номеров означают удалённые компоненты, запускать старые файлы не надо.
`apply.sh` применяет все перечисленные файлы одной транзакцией, с остановкой
на первой ошибке. libpq читает `PGHOST`, `PGPORT`, `PGUSER`, `PGDATABASE`,
`PGPASSWORD`/`PGPASSFILE` и `PGSSLMODE` из окружения. Для удалённой базы
используйте `PGSSLMODE=verify-full` и доверенный сертификат.

```sh
bash database/postgres/apply.sh
psql -X -v ON_ERROR_STOP=1 -f database/postgres/tests/smoke.sql
```

Проверка выполняется внутри транзакции и заканчивается `ROLLBACK`. Запускайте
её только в отдельной тестовой базе от владельца схемы. Она проверяет запись,
редактирование, версии документов, приватность, блокировку участника, ленту и
отсутствие прямого доступа API к таблицам. Её выполнение не подтверждает
работу T-SQL-варианта, Firebase или развёрнутого приложения.

## Модель и контракт

PostgreSQL сохраняет реляционные таблицы `authored`, `publishedin`, `commenton`
с внешними ключами для совместимости этой демонстрации; это не графовые
NODE/EDGE-таблицы. Все API-вызовы имеют те же параметры и порядок результатов,
что и основная реализация. Документные процедуры теперь находятся в `social`,
публикация возвращает `ContentID, RevisionID`, загрузка `ContentID,
DocumentVersionID`. Лента `social.usp_buildrecommendationfeed` сначала выдаёт
материалы авторов из подписок, затем сообществ пользователя, затем остальные
доступные материалы; внутри каждой группы сортирует по времени и ID.
Приватные и скрытые материалы проверяются заново при каждом запросе.

Firebase UID сопоставляет с SQL-пользователем только backend после проверки
ID token. Роль `coursework_api` создаётся без `LOGIN`; администратор настраивает
доступ отдельно. Она получает только `EXECUTE` на публичные функции, без
прямого доступа к таблицам. Функции имеют фиксированный `search_path`, а
создание объектов в `public` запрещено для `PUBLIC`. Ключи, пароли и реальные
строки подключения не коммитятся.
