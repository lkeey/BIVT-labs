# PostgreSQL для публичной демонстрации

Этот каталог — **параллельная реализация** функциональности курсовой. Основная
версия для отчёта и защиты остаётся на SQL Server 2025 и T-SQL в
[`../`](../). PostgreSQL здесь нужен для бесплатной демонстрации сайта и API;
скрипты не подменяют SQL Graph в курсовой.

Требуются PostgreSQL 16+ и расширения `vector` (pgvector) и `pgcrypto`. На Neon
`pgvector` доступен и включается командой `CREATE EXTENSION vector`, как
указано в [документации Neon](https://neon.com/blog/building-a-rag-application-with-llama-3-1-and-pgvector).
`00-schema.sql` включает оба расширения. Векторы хранятся как `vector(384)`;
поиск использует точное косинусное расстояние и русский полнотекстовый индекс.

## Порядок применения

На новой **отдельной** базе примените файлы по номеру:

| Файл | Назначение |
| --- | --- |
| `00-schema.sql` | Схемы, 33 таблицы, рёбра с внешними ключами, модель E5. |
| `01-access.sql` | Права чтения, актуальные фрагменты, русский индекс и outbox-триггеры. |
| `02-index-worker.sql` | Аренда заданий, OCR/embedding/граф в одной транзакции. |
| `03-social-write.sql` | Учётные записи и операции соцсети. |
| `04-social-read.sql` | Чтение с текущей проверкой доступа. |
| `05-rag.sql` | Гибридный поиск, история, проверенные цитаты и отзыв доступа. |
| `06-recommendations.sql` | Персональная лента по графу и явным действиям. |
| `07-security.sql` | Роли API и worker, `SECURITY DEFINER`, узкие разрешения. |

`apply.sh` запускает `psql` по этому порядку с остановкой на первой ошибке.
Вся первоначальная установка выполняется в одной транзакции: ошибка откатывает
все восемь файлов, включая настройку прав. Укажите параметры libpq через
окружение (`PGHOST`, `PGUSER`, `PGDATABASE`, `PGPASSWORD` или `PGPASSFILE`,
`PGSSLMODE`), затем из корня курсовой выполните:

```bash
bash database/postgres/apply.sh
```

Для удалённой базы включите TLS и проверьте сертификат сервера согласно
инструкции провайдера. Используйте прямое соединение администратора для миграций,
а не строку подключения API. Скрипты предназначены для первой установки;
изменение уже работающей схемы оформляйте новой пронумерованной миграцией.

## Доступ и соответствие T-SQL

Один экземпляр PostgreSQL хранит те же пять логических схем. `SQL Graph`
выражен таблицами рёбер с внешними ключами; упоминания и связи сохраняют
исходный фрагмент, координаты, уверенность и версию извлекателя. Текущий ACL
проверяется перед поиском, записью контекста LLM, сохранением цитат и чтением
ответа. Старые ревизии не входят в новые ответы. Файл PDF/DOCX хранится в
`bytea`, текст и фрагменты — в `text`, вектор — в `vector(384)`.

Миграция 07 создаёт роли `coursework_api` и `coursework_worker` без права входа.
Администратор создаёт **отдельные** роли подключения через SQL с паролями вне
репозитория и включает их в группы. Для Neon это особенно важно: роли, созданные
через Console/CLI/API, наследуют `neon_superuser`, а
[созданные SQL роли](https://neon.com/docs/manage/roles) могут быть ограничены
нужными правами. Например, после создания роли `coursework_api_login` через
`CREATE ROLE ... LOGIN PASSWORD ...`:

```sql
GRANT coursework_api TO coursework_api_login;
```

У прикладных ролей есть `EXECUTE` только на нужные функции; прямого доступа к
таблицам нет. Функции `SECURITY DEFINER` принадлежат владельцу миграций и имеют
фиксированный `search_path`. Go API проверяет Firebase ID token и только затем
передаёт `UserID`. Python worker вызывает `ops.*` по действительному `ClaimToken`.
`ops.has_pending_index_outbox()` позволяет запускать worker разово по расписанию:
постоянный опрос держал бы бесплатное вычисление Neon активным.

Одна база не выполняет OCR, создание E5-векторов или генерацию ответа LLM:
это делают прикладные компоненты. Публичная система заработает целиком после
развёртывания базы, API, worker, моделей и задания их секретов.
