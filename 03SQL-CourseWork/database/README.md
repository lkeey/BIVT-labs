# T-SQL курсовой

Скрипты рассчитаны на **SQL Server 2025** с установленным компонентом Full-Text Search.
В стандартном контейнере `mcr.microsoft.com/mssql/server:2025-latest`
компонент может отсутствовать (`FULLTEXTSERVICEPROPERTY('IsFullTextInstalled') = 0`):
для Linux установите пакет `mssql-server-fts` по
[инструкции Microsoft](https://learn.microsoft.com/en-us/sql/linux/install-upgrade/setup-full-text-search?view=sql-server-ver17)
или используйте сервер, где Full-Text уже включён. Скрипт 06 явно проверяет
этот компонент и прерывает установку, если его нет.
Работайте в отдельной базе `SocialNetworkDB`. Файлы применяются по номеру в имени;
`GO` распознаётся `sqlcmd` и SSMS. Повторный запуск сохраняет уже созданные таблицы
и индексы; изменения существующей схемы требуют отдельной миграции или новой пустой
учебной базы.

Скрипт 11 добавляет учебные данные и не зависит от процедур 12–13.
В чистой базе применяйте все скрипты 00–17 по порядку; в существующей базе
скрипт 12 также расширяет ограничения статусов и ролей членства. Нужны
`sqlcmd` и переменная окружения `SQLCMDPASSWORD`; пароль не помещайте в
командную строку или файлы репозитория. Из корня проекта:

```bash
sqlcmd -S localhost -d master -U sa -C -I -b \
  -Q "IF DB_ID(N'SocialNetworkDB') IS NULL CREATE DATABASE SocialNetworkDB;"
sql_status=0
for file in database/[0-1][0-9]-*.sql; do
  if ! sqlcmd -S localhost -d SocialNetworkDB -U sa -C -I -b -i "$file"; then
    sql_status=1
    break
  fi
done
test "$sql_status" -eq 0
```

Для Azure SQL Managed Instance Free используйте отдельную
[инструкцию развёртывания](../docs/azure-mi-free.md): она задаёт политику
`SQLServer2025`, доступ по TLS и применение этих же скриптов через endpoint
MI. Скрипты ранее проверялись на отдельном SQL Server 2025; результат на MI
пока не подтверждён.

`-b` завершает `sqlcmd` с ошибкой при ошибке SQL, `-I` включает
`QUOTED_IDENTIFIER` для фильтрованных индексов, а `-C` доверяет сертификату
локального учебного сервера. В производственном подключении настройте
проверяемый сертификат. Для повторного развёртывания используйте новую пустую
базу: демонстрационные данные и некоторые миграции рассчитаны на первый запуск.

## Состав модели

Одна база содержит **33 таблицы**: 5 узлов SQL Graph, 9 рёбер SQL Graph и 19
реляционных таблиц. Условия связей графа ограничивают типы узлов. Уникальные
индексы запрещают две текущие ревизии одного материала и дублирующиеся активные
связи. Бинарный оригинал PDF/DOCX хранится в `knowledge.DocumentVersion.FileBytes`
(`varbinary(max)`), введённый пользователем текст — в `PlainText`; из обоих
источников формируются ревизия текста и цитируемые фрагменты.

`knowledge.ChunkEmbedding.Embedding` использует `vector(384)`. Строка
`knowledge.EmbeddingModel` фиксирует
[`intfloat/multilingual-e5-small` на ревизии `fd1525a9fd15316a2d503bf26ab031a61d056e98`](https://huggingface.co/intfloat/multilingual-e5-small/tree/fd1525a9fd15316a2d503bf26ab031a61d056e98);
worker передаёт готовые векторы. Для учебного объёма поиск считает точное
`VECTOR_DISTANCE`, сочетает его с SQL Full-Text и графовыми связями. Поиск
выбирает только векторы именно этой модели и ревизии: другая активная модель
не смешивается с ними при ранжировании.
`FREETEXTTABLE` иногда возвращает подходящий фрагмент с `RANK = 0` (например,
из-за шумовых слов в вопросе); поэтому такой фрагмент получает положительный
`TextScore = (RANK + 1) / 1001`, а отсутствие совпадения — нулевой балл.

`assistant.usp_SearchRag` принимает массив JSON из 384 чисел и необязательный
`@CommunityID`; недоступное сообщество отклоняется. Завершённый ответ
сохраняется через `assistant.usp_SaveRagAnswer` только с непустой проверенной
цитатой. Если доступных источников нет, `assistant.usp_SaveRagNoSources`
помечает ход `NO_SOURCES` без генерации ответа.
`assistant.usp_StartRagSession` и `assistant.usp_StartRagTurn` создают историю
запроса, а `assistant.usp_RecordRetrievedChunks` сохраняет только текущие
доступные фрагменты, которые backend собирается передать LLM.
`assistant.usp_GetRagTurn` возвращает `REVOKED` без текста ответа, если цитаты
или использованные фрагменты перестали быть доступны. Процедура
`knowledge.usp_GetDocumentFile` выдаёт оригинал только для текущей готовой
версии документа после проверки ACL.
`social.usp_ListPendingMemberships` показывает заявки только владельцу или
активному администратору сообщества; курсор основан на `MembershipID`.

`social.usp_CreateCommunity`, `usp_RequestMembership`, `usp_SetMembership`,
`usp_LeaveCommunity`, `usp_SetFollow`, `usp_SetReaction` и
`usp_ModerateContent` реализуют основные записи HTTP API. Владелец сообщества
определяется `Community.OwnerUserID`; блокировка участника закрывает доступ
также к открытому сообществу. Все эти процедуры ожидают `UserID` от
доверенного backend и сами не аутентифицируют вызывающего.
`assistant.usp_RevokeContentAccess` при отзыве поста также скрывает его
комментарии и ставит на удаление их поисковые и графовые проекции; SQL ACL
закрывает доступ к ним сразу, до обработки очереди.

`ops.usp_ClaimIndexOutbox` возвращает `ClaimToken`. Worker читает исходник
через `ops.usp_GetClaimedIndexSource`, продлевает аренду через
`ops.usp_RenewIndexLease` и завершает её атомарным `ops.usp_CommitIndexResult`
или `ops.usp_CommitIndexDeletion`. Устаревший токен не может записать индекс.
`ops.usp_RequeueExpiredIndexOutbox` возвращает истёкшие задания в очередь;
после третьей неудачи источник получает статус `FAILED`.
Для извлечённого ребра `ops.usp_CommitIndexResult` проверяет, что его
доказательный отрывок в том же фрагменте включает упоминания обеих сущностей.

Go API проверяет Firebase ID token до вызова
`auth.usp_GetOrCreateFirebaseUser`; SQL сам не проверяет подпись токена.
Для API и worker созданы роли `coursework_api` и `coursework_worker` с правом
`EXECUTE` только на нужные процедуры. DBA должен создать отдельные SQL-логины,
пользователей базы и добавить их в соответствующие роли. Пароли и параметры
подключения не входят в репозиторий.

Исторические ревизии остаются для аудита, но представления поиска используют
только опубликованное текущее содержание. Проверка доступа выполняется по
активной учётной записи, видимости сообщества и активному членству; закрытое
сообщество также доступно владельцу, а действующая блокировка запрещает чтение
любого сообщества. Комментарий наследует доступ от исходного
поста. Извлечённые рёбра хранят фрагмент-основание, координаты, уверенность и
версию извлекателя; имена сущностей автоматически не объединяются.
