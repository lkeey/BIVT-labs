# SQL Server: реляционная модель и один граф подписок

Основная реализация рассчитана на SQL Server 2025. В ней **12 обычных таблиц и ровно 2 графовые**:

- `auth`: `UserAccount`, `UserProfile`, `ExternalIdentity` (Firebase UID → пользователь).
- `social`: `Community`, `ContentItem`, `PostRevision`, `CommentRevision`, `DocumentDetail`, `DocumentVersion`, `MemberOf`, `ReactTo`.
- `ops`: `AuditEvent`.
- Граф: `social.UserNode AS NODE`, `social.Follows AS EDGE`. Узел создаётся триггером при регистрации пользователя. Все остальные связи реализованы FK и JOIN.

`ContentItem` хранит автора, сообщество и родительский пост комментария. Составной FK запрещает комментарий к документу и к посту другого сообщества. Уникальные фильтрованные индексы обеспечивают одну текущую редакцию/версию и одно незавершённое членство. Реакция уникальна по паре пользователь–материал.

## Установка без потери старых данных

Это **новая схема, не автоматическая миграция** старой графовой базы. Создайте отдельную пустую учебную БД, например `CourseworkRelational`, и направьте приложение на неё. Скрипт `00` обнаруживает старые графовые аккаунты либо таблицы удалённых подсистем и завершает установку ошибкой. Не обходите эту проверку и не запускайте последующие файлы после ошибки. Скрипты не выполняют `DROP DATABASE`, `TRUNCATE` или массовое удаление старых данных.

Старую БД сохраните вместе с резервной копией. Для переноса существующих данных нужен отдельный проверенный план: восстановить автора/сообщество/родителя из прежних рёбер, перенести членства и реакции в FK-таблицы, сохранить все версии документов, исходные байты и контрольные суммы, сверить количество строк и ACL. Только после проверки переключать приложение. Такой перенос намеренно не запускается этим PR.

Применяйте файлы в порядке имён, останавливаясь при любой ошибке (`sqlcmd -b`):

```bash
# SQLCMDPASSWORD задаётся вне репозитория; -d указывает НОВУЮ учебную базу.
for file in database/*.sql; do
  sqlcmd -S localhost,1433 -U sa -d CourseworkRelational -C -b -i "$file" || exit 1
done
sqlcmd -S localhost,1433 -U sa -d CourseworkRelational -C -b -i database/tests/smoke.sql
```

`11-demo.sql` необязателен: пропустите его вне демонстрационной установки. Учебные аккаунты не имеют паролей/Firebase credentials. Smoke-тест создаёт собственные уникальные записи и откатывает транзакцию даже при сбое; запускайте его только в учебной БД. Пропуски в номерах файлов после удаления подсистем ожидаемы.

## Контракты и поведение

- `social.usp_PublishContent` возвращает `(ContentID, RevisionID)`.
- `social.usp_SaveDocumentVersion` возвращает `(ContentID, DocumentVersionID)`; чтение документов также находится в `social`.
- `social.usp_RevokeContentAccess` скрывает/помечает удалённым материал, не уничтожая оригинальные файлы и историю. Удаление поста скрывает комментарии.
- `social.usp_BuildRecommendationFeed` возвращает `(Rank, ContentID, Kind, Score, ReasonCode, ReasonText, CommunityID, AuthorUserID)`. Сначала авторы с подпиской, затем собственные/присоединённые сообщества, затем свежие материалы; время и ID дают стабильную сортировку. Источником служит актуальный ACL, а не сохранённый результат рекомендаций.
- Приватное сообщество недоступно постороннему; BLOCKED/BANNED запрещает чтение даже публичного сообщества. Владелец может публиковать без отдельной записи членства.
- Документы PDF/DOCX сохраняются в `varbinary(max)`, текстовые в `nvarchar(max)`, версии содержат размер и SHA-256. Готовы сразу после сохранения; `ProcessingStatus=READY` оставлен в ответе чтения для совместимости API. OCR, векторного поиска, RAG, chunks, AI-диалогов, outbox и фонового индексатора нет.
- `coursework_api` имеет права выполнения процедур, а не прямой доступ к таблицам. Проверку Firebase ID token выполняет сервер; UID передаётся в `auth.usp_GetOrCreateFirebaseUser` только после проверки.

`postgres/` сохранён как отдельный альтернативный вариант, не как автоматически взаимозаменяемая реализация API SQL Server. Ограничения и статус сравнения описаны в его README.
