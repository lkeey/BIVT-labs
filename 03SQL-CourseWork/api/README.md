# HTTP API курсовой

[`openapi.yaml`](openapi.yaml) описывает 30 маршрутов Go API. Все `/api/v1`
требуют Firebase ID token. Backend проверяет подпись, проект, срок и отзыв,
затем связывает UID с `auth.UserAccount`. SQL проверяет доступ к объекту.
Браузер не получает доступ к БД и не выбирает личность через `UserID`.

- `bigint` передаётся строкой; время в UTC RFC 3339.
- Страницы возвращают `items` и непрозрачный `nextCursor`.
- `401`: недействительная Firebase-сессия; `403`: запрет операции;
  `404`: объект отсутствует или скрыт от пользователя; `409`: конфликт.
- Посты и комментарии возвращают `contentId`, `revisionId`.
- Загрузка документа возвращает `201`, `contentId`, `documentVersionId` и
  `processingStatus: READY`. Файл сохраняется сразу, без фоновой обработки.
- Лента использует `social.usp_BuildRecommendationFeed`, проверяет доступ и
  ранжирует подписки, сообщества и новые материалы. AI-маршрутов нет.

Проверка из корня репозитория:

```sh
python3 -m pip install PyYAML==6.0.3
python3 03SQL-CourseWork/tools/verify_contract.py
```

Проверяются маршруты Go, `$ref`, path-параметры и отсутствие удалённых
маршрутов. Это не сквозной тест Firebase и базы данных.
