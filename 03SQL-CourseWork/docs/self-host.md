# Публикация без платного хостинга и банковской карты

Этот вариант использует **имеющийся постоянно включённый x86-64 компьютер** с
Ubuntu 24.04. На нём работают SQL Server 2025 Express, Go API, Python worker,
сервис embeddings и локальная модель ответа. Сайт остаётся на бесплатном
[Firebase Hosting](https://bivt-labs-sql-coursework.web.app/); публичный HTTPS
адрес API предоставляет [Tailscale Funnel](https://tailscale.com/docs/features/tailscale-funnel).
По [тарифам Tailscale](https://tailscale.com/pricing) Personal бесплатен для
личного использования, а Funnel доступен на всех тарифах. Банковская карта,
домен и проброс портов на домашнем роутере для этой схемы не требуются.

Это **не бесплатная облачная VM**: компьютер, интернет и электричество уже
должны быть доступны. API работает, только пока компьютер включён и подключён
к сети. Funnel находится в beta, имеет ограничение пропускной способности и
не даёт гарантии доступности. Для учебной демонстрации это допустимый вариант;
не следует обещать круглосуточную работу без проверки своего оборудования.

## Требования к компьютеру

- x86-64 процессор, Ubuntu 24.04, не менее 12 ГБ RAM и достаточно места для
  SQL, оригиналов документов, OCR, E5, LLM и резервных копий. 12 ГБ —
  стартовая оценка всего стека, а не гарантия производительности. При нехватке
  памяти выбирайте меньшую локальную LLM и измеряйте время ответа.
- Постоянное питание и доступ в интернет. Используйте накопитель с
  поддерживаемой SQL Server файловой системой ext4 или XFS. SQL Server 2025
  на Apple Silicon/ARM через эмуляцию здесь не предусмотрен: официальные
  [требования Microsoft](https://learn.microsoft.com/en-us/sql/linux/sql-server-linux-setup)
  указывают x64.
- Учётная запись Tailscale на бесплатном Personal plan. Для Funnel в tailnet
  должны быть включены MagicDNS, HTTPS и разрешение Funnel; при первой
  настройке CLI предложит открыть страницу включения функции.

## Запуск

1. Выполните шаги установки SQL Server Express, Full-Text, TLS, T-SQL-скриптов
   и прикладных служб из [инструкции для одного сервера](vps-express.md) и
   [шаблонов systemd](../deploy/vps/README.md). Отличия: вместо VPS
   используется свой компьютер; публичный Caddy и открытие входящих портов
   `80/443` не нужны. Go API слушает только `127.0.0.1:8081`, SQL —
   `127.0.0.1:1433`, сервис embeddings — `127.0.0.1:8765`, локальная LLM —
   loopback. Не публикуйте SQL и worker через Funnel.
2. Установите Tailscale по [официальной инструкции для Linux](https://tailscale.com/docs/install/linux),
   войдите в личный tailnet и проверьте, что Go API отвечает локально:

   ```sh
   sudo systemctl enable --now tailscaled
   sudo tailscale up
   curl --fail-with-body http://127.0.0.1:8081/healthz
   curl --fail-with-body http://127.0.0.1:8081/readyz
   ```

3. Опубликуйте **только Go API**. `--bg` сохраняет Funnel при перезагрузке
   устройства и рестарте Tailscale согласно
   [документации CLI](https://tailscale.com/docs/reference/tailscale-cli/funnel).
   Команда покажет адрес вида `https://<имя-узла>.<tailnet>.ts.net`:

   ```sh
   sudo tailscale funnel --bg --https=443 http://127.0.0.1:8081
   tailscale funnel status
   ```

4. Проверьте по опубликованному HTTPS-адресу `/healthz` и `/readyz`, затем
   Firebase-вход, публикацию, индексацию и RAG-ответ с доступными цитатами.
   В [конфигурации сайта](../web/public/config.js) задайте `apiBaseUrl` как
   `https://<имя-узла>.<tailnet>.ts.net/api` и включите `backendReady: true`
   **только после** сквозной проверки. Переопубликуйте сайт на Firebase
   Hosting. CORS в окружении API оставьте строго
   `https://bivt-labs-sql-coursework.web.app`.
5. Настройте резервное копирование БД на независимый носитель и регулярную
   проверку восстановления. Автозапуск `mssql-server`, API, worker, embedding,
   Ollama и `tailscaled` проверяйте после перезагрузки. Сам Funnel не
   обеспечивает сохранность данных.

Адрес `*.ts.net` зависит от имени узла и tailnet. После их переименования
обновите URL в конфигурации сайта и повторите публикацию. Пока такого
компьютера нет и сквозной сценарий не проверен, публичный сайт остаётся
демонстрацией интерфейса без подключённого backend.
