# Архитектура

Браузер входит через Firebase Authentication и отправляет ID token в Go API.
Backend проверяет подпись, issuer, audience, срок и отзыв токена; SQL UserID
вычисляется по проверенному Firebase UID. Клиент не назначает себе SQL-личность.

API вызывает процедуры SQL Server через ограниченную роль coursework_api.
Реляционные таблицы содержат предметные данные и ограничения целостности.
SQL Graph используется только для подписок пользователей и учебного обхода
через общие подписки. В PostgreSQL подписки представлены обычной таблицей.

Лента строится SQL-запросом по доступным публикациям, подпискам, сообществам
и времени. Право читать закрытый материал проверяется при каждой выдаче,
включая скачивание документа. Членство и реакции — обычные таблицы связей.

Файлы и их версии остаются в базе. OCR, embeddings, граф знаний, очередь
индексации, чат-модель, RAG-сессии и ссылки на фрагменты исключены.
Firebase отвечает за вход и размещение статического сайта, а не заменяет
реляционную базу курсовой. Новых расходов и облачных ресурсов PR не создаёт.

Существующие базы не преобразуются автоматически. Перед переносом реальных
данных необходимы резервная копия и отдельная миграция с проверкой файлов,
авторства, членства, реакций и доступа к закрытым сообществам.
