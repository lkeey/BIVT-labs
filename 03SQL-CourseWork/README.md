# Курсовая: реляционная социальная сеть

Основная реализация — SQL Server 2025/T-SQL. Пользователи, сообщества, членство,
публикации, комментарии, реакции и версии документов связаны обычными PK/FK.
Один учебный социальный граф содержит **две** SQL Graph таблицы: вершины
пользователей и рёбра подписок. ИИ, RAG, векторов и фоновой индексации нет.

## Компоненты

- [database](database/README.md): схема, ограничения, процедуры и учебные данные.
- [backend](backend/README.md): Go HTTP API, Firebase ID token → SQL UserID.
- [web](web/README.md): статический клиент, Firebase Authentication и Hosting.
- [api](api/openapi.yaml): OpenAPI.
- [PostgreSQL](database/postgres/README.md): отдельный совместимый вариант для демо;
  не заменяет SQL Server и не реализует SQL Graph.
- [Модель](docs/data-model.md), [архитектура](docs/architecture.md),
  [план защиты](docs/coursework-outline.md), [запуск](docs/deployment.md).

## Безопасный переход

Новая схема предназначена для новой пустой учебной базы. Старую базу не удалять:
старые графовые связи и документы требуют отдельной проверенной миграции.
Скрипты останавливаются при обнаружении несовместимой старой схемы.
Сами документы сохраняются в реляционной модели, а не удаляются вместе с RAG.
Изменение исходников и PR не означают, что действующая база или сайт обновлены.

## Проверки

```sh
cd backend
go mod verify
go test ./...
go vet ./...
go build ./...
cd ..
python tools/verify_contract.py
for file in web/public/*.js; do node --check "$file"; done
```

Для Python-проверки нужен PyYAML. Статические проверки не заменяют применение
T-SQL на SQL Server и проверку операций с правами двух разных пользователей.
