# Сайт курсовой

Статический JavaScript-интерфейс к [HTTP API v1](../api/openapi.yaml): лента,
сообщества, публикации и комментарии, документы, RAG-ответы с источниками. В
репозитории нет демонстрационных материалов, выдаваемых за реальные данные:
экраны показывают ответ backend или честное пустое состояние. Сайт не обращается
к SQL Server, LLM и OCR напрямую.

## Структура и запуск

| Файл | Назначение |
| --- | --- |
| `public/index.html` | Семантические экраны и формы |
| `public/app.js` | Навигация, состояние и операции API |
| `public/api.js` | Единственная точка HTTP-запросов и обработки ошибок |
| `public/styles.css` | Адаптивная светлая тема |
| `public/config.js` | Публичный адрес API, загружаемый при открытии страницы |
| `firebase.json` | Публикация только `public/` на Firebase Hosting |

Локально запустите сервер статических файлов из `web/public`, например:

```bash
cd 03SQL-CourseWork/web/public
python3 -m http.server 8080
```

Откройте `http://localhost:8080`. Открытие `index.html` через `file://` не
поддерживается из-за JavaScript-модулей. Backend должен быть доступен отдельно;
если его нет, подключение покажет ошибку сети и рабочие экраны не откроются.
При совместном локальном запуске задайте backend `ADDR=:8081` и
`CORS_ORIGIN=http://localhost:8080`, а в форме подключения сайта укажите
`http://localhost:8081/api`. Иначе сайт и API будут пытаться занять один порт.

## Конфигурация

В `public/config.js` задайте `apiBaseUrl`. По умолчанию это `/api` на том же
домене, что сайт. Для отдельного backend укажите полный HTTPS-адрес, например
`https://api.example.org/api`. Адрес также можно изменить в форме подключения
в текущей вкладке. Backend должен разрешить домен Firebase Hosting по CORS,
включая заголовок `Authorization`.

Для входа через Google заполните `firebaseConfig` публичными настройками web
app Firebase (`apiKey`, `authDomain`, `projectId`, `appId`), включите Google
в Firebase Authentication и добавьте домен Hosting в разрешённые домены.
Кнопка входа появится автоматически. Код загружает
[Firebase Web SDK с официального CDN](https://firebase.google.com/docs/web/alt-setup)
только при нажатии на неё и использует память вкладки как хранилище входа.
SDK получает свежий ID token перед каждым запросом API.

`config.js` — **публичный** файл. SQL-пароли, Firebase Admin credentials,
секреты LLM и приватные ключи здесь недопустимы. Не вносите реальные токены в
репозиторий или параметры URL.

До настройки Firebase web app для интеграции доступна ручная вставка
действующего Firebase ID token. Сайт отправляет его как
`Authorization: Bearer` и проверяет текущего пользователя
через `GET /v1/auth/sessions/current`. Токен не сохраняется в localStorage,
sessionStorage или cookie; обновление страницы завершает локальную сессию.
Срок действия ручной сессии берётся из `exp` токена для удобства клиента,
но доверенная проверка подписи, срока, `issuer` и `audience` выполняется только
backend. Настроенный Firebase Auth SDK обновляет ID token автоматически; без
настроек проекта кнопка входа отсутствует. Всплывающее окно входа через Google
может блокироваться некоторыми мобильными браузерами; вариант с redirect
потребует отдельного решения по хранению состояния между перезагрузками.

## Публикация на Firebase Hosting

После создания Firebase-проекта и настройки backend:

```bash
cd 03SQL-CourseWork/web
firebase deploy --only hosting --project YOUR_PROJECT_ID
```

Команда приведена для владельца проекта; публикация из этой задачи не
выполнялась. `firebase.json` размещает только содержимое `public/`. Если
Firebase Hosting и API находятся на разных доменах, в `config.js` нужен
полный HTTPS-адрес backend; правило rewrite в Hosting не настроено.

## Поведение и границы

- Закрытые сообщества и материалы фильтрует backend. Клиент скрывает действия
  без активного членства для удобства, но это не заменяет серверную ACL.
- Лента получает причины рекомендаций из API и повторно загружает материал;
  недоступные к моменту чтения материалы не показываются.
- Загруженный документ проверяется по ID до `READY` или `FAILED`. Клиент
  предварительно ограничивает файл 10 МиБ, сервер проверяет размер и содержимое.
- RAG-запрос может выполняться до 90 секунд. При `NO_SOURCES` показывается отсутствие подходящих
  материалов; при `410` сохранённый ответ и цитаты скрываются. Кнопка источника
  заново читает материал с текущим токеном.
- Пользовательские тексты выводятся через `textContent`, без HTML-интерпретации.
- Оригинал готового текстового документа, PDF или DOCX скачивается через
  авторизованный запрос `GET /v1/documents/{documentId}/file`; прямой переход
  по URL с Bearer-токеном не используется.

Для интеграции используйте контракт `../api/openapi.yaml` и рабочий адрес
backend. Этот frontend не содержит фиктивного API. Сквозной запуск с Firebase,
SQL Server, OCR и моделью ответа требует отдельной настройки этих сервисов.
