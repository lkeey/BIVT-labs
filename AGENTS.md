# Правила работы агентов

## Контекст монорепозитория

- Репозиторий содержит независимые учебные проекты. Карта каталогов и команды
  приведены в [README.md](README.md); процесс веток и pull request — в
  [CONTRIBUTING.md](CONTRIBUTING.md).
- Для файлов учебного проекта применяйте его `AGENTS.md`. Обращайтесь к README
  проекта за командами запуска и проверки, когда задача затрагивает код, данные
  или запуск. Для курсовой в `03SQL-CourseWork/` используйте `$sql-coursework`
  при проектировании или изменении схемы, графа, RAG-запросов и рекомендаций.
- Соблюдайте границы каталогов: не переносите код, данные или решения между
  дисциплинами без явной необходимости и не включайте в изменение посторонние
  файлы.

## Изменения и проверка

- Новую задачу начинайте в отдельной ветке от `origin/main`; если задача уже
  ведётся в своей ветке, продолжайте в ней. Изменения в `main` принимаются
  через pull request.
- Выбирайте только относящиеся к задаче файлы для staging. Перед отправкой
  просмотрите полный diff и выполните проверки, указанные README затронутого
  проекта.
- Обновляйте документацию проекта, когда меняются его команды, структура или
  поведение. Не утверждайте, что проверка прошла, если она не запускалась.
- Не считайте корневой `BIVT-labs.sln` общей сборкой монорепозитория. Для C#
  работ собирайте конкретный `.csproj`, указанный в документации лабораторной.

## Что не добавлять в Git

- Не добавляйте секреты, локальные конфигурации, токены, пароли и файлы `.env`.
- Не добавляйте системные и сборочные артефакты: `.DS_Store`, `__pycache__/`,
  `*.pyc`, `.coverage`, `bin/`, `obj/`, временные и локальные базы данных.
- Не удаляйте и не перезаписывайте существующие учебные данные и отчёты без
  явной связи с задачей. Если назначение файла неясно, сначала проверьте ссылки
  на него в README и коде проекта.
